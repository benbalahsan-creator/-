# דשבורד כוח אדם להנהלה

פלטפורמה שמציגה להנהלת העמותה תמונת מצב של כוח האדם: מצבת עובדים, משרות, קליטות ועזיבות, תחלופה, ותק, גילאים ופילוחים.

**שלב נוכחי:** הנתונים נטענים מקובץ אקסל/CSV שיוצא מ-Be360.
**שלב הבא:** חיבור ישיר ל-Be360 API, כשיתקבלו פרטי הגישה.

## הרצה

```bash
cd app
npm install
npm run dev      # פיתוח: http://localhost:5173
npm run build    # בנייה לפרודקשן → app/dist
```

## איך זה עובד

1. **טעינת קובץ:** ‎.xlsx‎ או ‎.csv‎. כל העיבוד מתבצע בדפדפן, והנתונים לא נשלחים לשום שרת.
2. **התאמת עמודות:** המערכת מזהה לבד כותרות נפוצות בעברית ובאנגלית ("שם העובד", "אגף", "תאריך קליטה", "% משרה" ועוד). אפשר לתקן ידנית. המיפוי נשמר בדפדפן לפעם הבאה.
3. **דשבורד:** אפשר לסנן לפי מחלקה, סניף וסוג העסקה.

שדות חובה: שם, מחלקה, תאריך תחילת עבודה. שאר השדות אופציונליים, ורכיבי הדשבורד שתלויים בהם מוצגים רק כשהשדה קיים בקובץ.

### מדדים

| מדד | הגדרה |
|---|---|
| עובד/ת פעיל/ה | תאריך התחלה ≤ היום, ואין תאריך סיום או שתאריך הסיום בעתיד |
| FTE | סכום היקפי המשרה ÷ 100. ערכים כמו 0.5 מתפרשים כ-50% |
| שיעור תחלופה שנתי | עוזבים ב-12 החודשים האחרונים ÷ ממוצע המצבת (לפני שנה והיום) |
| מגמה חודשית | מצבת בסוף כל חודש, משוחזרת מתאריכי ההתחלה והסיום |

## מבנה הקוד (`app/src`)

```
data/
  types.ts              מודל העובד הקנוני (Employee)
  fields.ts             הגדרות שדות + זיהוי אוטומטי של כותרות
  normalize.ts          המרת שורות גולמיות → Employee (תאריכים ישראליים, תאריכי אקסל, מגדר…)
  sources/
    DataSource.ts       ממשק אחיד לכל מקור נתונים
    excelSource.ts      אקסל / CSV  ← בשימוש היום
    be360ApiSource.ts   שלד לחיבור ל-API  ← ימולא כשיתקבל ה-API
    sampleSource.ts     נתוני דמו פיקטיביים
analytics/metrics.ts    כל חישובי המדדים (בלתי תלוי ב-UI)
components/             מסכי טעינה, מיפוי ודשבורד
```

## חיבור ל-Be360 API (בהמשך)

הדשבורד לא תלוי במקור הנתונים. כדי לעבור ל-API צריך:

1. לממש את `Be360ApiSource.load()` לפי התיעוד של Be360: כתובת, אימות, עימוד (pagination) ומבנה התשובה.
2. **לא לשים מפתח API בקוד הדפדפן.** מומלץ להקים שרת ביניים קטן (למשל Cloudflare Worker, Azure Function או Node) שמחזיק את המפתח, מבצע את הקריאה ל-Be360 ומחזיר לדשבורד רק את השדות הנדרשים.
3. להוסיף כניסה מאובטחת למשתמשי ההנהלה, כי מדובר בנתונים אישיים של עובדים.

מה צריך לברר מול Be360:
- האם קיים API ציבורי או API לשותפים, ואיפה התיעוד
- שיטת האימות (API key, OAuth וכו')
- endpoint לרשימת עובדים, כולל עובדים שעזבו (בלעדיהם אי אפשר לחשב תחלופה ומגמות)
- מגבלות קצב (rate limits)
